# Speechara macOS auto-updates

Speechara uses Sparkle 2 and the public update feed at:

```text
https://updates.speechara.ai/appcast.xml
```

Release files are served from:

```text
https://updates.speechara.ai/releases/
https://updates.speechara.ai/release-notes/
https://updates.speechara.ai/download/
```

## App configuration

The app has these Sparkle keys in `Speechara/Info.plist`:

```text
SUFeedURL = https://updates.speechara.ai/appcast.xml
SUPublicEDKey = +er2tmbbGKAStULAg+A/243msSxKOj1iYOA35HecFho=
SUEnableAutomaticChecks = true
SUScheduledCheckInterval = 86400
```

The matching private EdDSA key was generated by Sparkle's `generate_keys` tool
and stored in the local macOS Keychain under account:

```text
ai.speechara.mac
```

For local publishing, the same key is also exported to:

```text
~/.config/speechara/sparkle_ed_private_key
```

The file is mode `0600` and is used by `Scripts/publish_update.sh` because
`generate_appcast` may not have Keychain access in non-interactive shells. Do
not commit exported private keys. For CI, store the exported key as a secret,
then pass it to `Scripts/publish_update.sh` as `SPARKLE_ED_PRIVATE_KEY` or
`SPARKLE_ED_KEY_FILE`.

## Publishing an update

1. Bump `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in the Xcode project.
2. Add a `## <version> - YYYY-MM-DD` section to `CHANGELOG-macOS.md`.
3. Run:

```bash
./Scripts/publish_update.sh \
  --sign-identity "Developer ID Application: Your Company (TEAMID)"
```

The script builds a signed/notarized DMG, generates the signed Sparkle appcast,
generates release notes plus the macOS history page, and uploads files over SFTP
in this order:

```text
/www/releases/Speechara-<version>.dmg
/www/release-notes/Speechara-<version>.html
/www/history/mac/index.html
/www/download/Speechara.dmg
/www/download/latest.json
/www/appcast.xml
```

Uploading `appcast.xml` last prevents users from seeing an update before the DMG
and release notes are already available. Sparkle still points to the release
notes page for the exact version, and that page links to:

```text
https://updates.speechara.ai/history/mac/index.html
```

`CHANGELOG-macOS.md` is the source of truth for both pages. Use `--release-notes`
only when intentionally overriding the generated per-version page; the full
history page is still generated from the changelog.

The clean URL `https://updates.speechara.ai/history/mac` needs an nginx rule or
redirect on the updates origin. Until that route is configured, generated
release notes link to the explicit `index.html` URL.

Production publishes must not use `--no-layout`. The release DMG keeps the
branded Finder background, the app icon on the left, the Applications shortcut
on the right, and the drag arrow between them. `publish_update.sh` rejects
`--no-layout` when deploying so website downloads and Sparkle updates use the
same polished installer view.

## Website download URL

The public website should link to:

```text
https://updates.speechara.ai/download/mac
```

The deploy script refreshes these stable files on every release:

```text
/www/download/Speechara.dmg
/www/download/latest.json
```

Configure nginx once so `/download/mac` redirects to the stable DMG path, not a
versioned release path:

```nginx
location = /download/mac {
    add_header Cache-Control "no-cache" always;
    return 302 /download/Speechara.dmg;
}

location = /download/Speechara.dmg {
    alias /www/download/Speechara.dmg;
    default_type application/x-apple-diskimage;
    add_header Cache-Control "no-cache" always;
    add_header Accept-Ranges bytes always;
}

location = /download/latest.json {
    alias /www/download/latest.json;
    default_type application/json;
    add_header Cache-Control "no-cache" always;
}
```

This keeps the website URL stable while Sparkle continues using immutable,
versioned DMGs under `/releases/`.

For a local dry run:

```bash
./Scripts/publish_update.sh --no-deploy --skip-notarization
```

For local headless packaging tests where Finder layout is not available:

```bash
./Scripts/publish_update.sh --no-deploy --skip-notarization --no-layout
```

For the first real `Speechara-1.0.1.dmg`, purge the exact Cloudflare URL if the
previous cached 404 is still active:

```text
https://updates.speechara.ai/releases/Speechara-1.0.1.dmg
```
